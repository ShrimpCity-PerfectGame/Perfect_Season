# Gridspin 2.0.0 — status and outstanding work

**Written 2026-09-23. Hand this to a new session along with CLAUDE.md.**

2.0.0 is on `staging` at commit `fc6180a`, deployed and verified on the staging site. It is **not
promoted** and should not be until the blockers below are closed. Three adversarial sweeps have been run
(16, ~40 and ~45 findings); sweeps one and two are fixed, sweep three's findings are the list here.

## 2. What 2.0.0 contains

Bug-fix release, no new modes. The substantial pieces: guests behave like guests everywhere a name is
shown; a patchy connection can't cost you an account; `profiles.rev` stops a finished season being
overwritten by the DNF "Run it back" fires; GM can't deal a board you can't afford anybody on; the bot's
par is measured correctly (seasons had been scoring ~17% low); Championship's Flex is capped so it can't
be drafted into a guaranteed 20–0; accessibility and a 12px floor; security headers and one address per
page; and a service worker that doesn't file OAuth codes.

Two things were **reverted** before release and must not be reintroduced casually:

- **"A re-spin may not repeat a team."** `rerollCandidate` is seeded, so narrowing its pool changes which
  board an existing code deals — 69.7% of team re-spins. Every draft re-spun on the live client and
  finished on the new one would be refused as an illegal roster. Wants server-issued seeds under it, not a
  client-side rule. See CLAUDE.md's note.
- **A `botWalk` reserve based on the real cost of remaining boards.** Measured no benefit; reverted to keep
  the ladder stable.

## 3. Release blockers

Nothing below is speculative — each was demonstrated by a reviewer with a concrete repro.

### 3.1 The roster tile bypasses every draft rule — `perfect-season.jsx:4286`

`draft()` has **two** call sites. The Lock in button enforces `tooExpensive`, `leavesNothing` and
`noBoardLeft`; the roster-slot tile is `disabled={!target}` and enforces none of them.

```
GM, $19M left, LeSean McCoy $42M on PHI|2
  Lock in:      "🔒 Lock in · Flex - $42M (over cap)"   disabled
  Roster tile:  "Draft LeSean McCoy to Flex"            live
  after tap:    $173M / $150M  →  submit-run: 400 "over the salary cap"
```

**This predates 2.0 and means the GM cap has never been enforced in the UI.** The player is told "it will
be included the next time a save goes through", which is false. Fix both call sites together.

### 3.2 `botPar`'s rescue can still collapse — `game-logic.mjs:526`

`if (best == null) return cheap;` returns the spend-least walk with no ceiling applied. `bestPossible`
holds the `MIN_SALARY` reserve and returns null when nothing clears it — i.e. it strands the same way the
greedy bot does, exactly when the rescue is needed.

Demonstrated with code `49BT4M`, GM + Fantasy: a legal $148M roster scoring 94.7 gets par **44.10** instead
of ~93.6 → **649 ladder points instead of ~115**, 64 coins instead of 11, and it clears `SCOUT_MIN_POINTS`
(220) so a below-median season also earns the Scout badge and its 300 coins. One in ~80,000 by accident,
but free-mode codes are the client's own choice, so it is findable offline in seconds.

### 3.3 The guest upload gate is cosmetic — `supabase/migration-profiles.sql:650-657`

`save_profile` and `set_avatar` are gated. The six `avatars` **storage bucket policies are not** — a
reviewer created an anonymous account, watched both functions refuse it, then inserted **10 files**
directly, stopped only by the per-folder cap. Bucket is `public = true`, so each has a working
unauthenticated `gridspin.app` URL, on an account that can be remade indefinitely.

`equip_item` and `set_showcase` (`migration-shop.sql:247,251,255,286`) also write `profile_details` for a
guest, which falsifies `tests/test-profile-data.mjs:147`'s "a refused guest leaves no details row".

### 3.4 A failed duel finish bricks Duel permanently — `match-pick/index.ts:159-186`

The 16th pick inserts, grading fails → 500, `matches.status` stays `drafting`. Both screens sit on
"Working out the result…" and **nothing can post again** (both send paths need `drafting` *and* zero picks
left). Then `create_match` prefers an existing `drafting` match, so tapping Duel returns both players into
the dead match — for every future duel. Recovery is the runbook SQL, by hand.

Second route in: a powerup landing between a concurrent request's match read and its insert silently drops
a pick (`versus-logic.mjs:343-348`'s `take()` returns silently), and grading then returns null.

### 3.5 `mod_act` has no guest guard — `supabase/migration-moderation.sql:173`

`report_player` was gated; the dangerous action wasn't. **Every report already in production against a
guest is a live trap** — `mod_queue` still lists them, Rename still works, and the account ends up
`guest=false` holding a real username on an anonymous session, with `claim_username` answering
`already_named` and `KeepSeasons` gated on `isGuest`. No way to attach an email. See pre-flight query 4.

### 3.6 The deploy order in CLAUDE.md loses GM seasons

CLAUDE.md says run `deploy:fn:prod` "after promoting" — but the client auto-redeploys on merge, creating
a new-client/old-function window that two other lines say never to create. Measured **4.29% of GM seasons
refused** in that window. **For production, deploy the Edge Functions from `staging` before the merge.**

## 4. Should fix

### The daily is still rehearsable (`perfect-season.jsx:3740`)

The forgery guard is server-side, but the attack needs no server: `startCode` accepts any `[A-Z0-9]{4,8}`,
`finish()` computes the whole season locally, and it only submits `if (user)`. Signed out, `QMNAR900`
(found in 1.64s) deals today's daily bit for bit and `submit-run` is never consulted. Also the ±2 day
window leaves T+3 onward accepted — collisions demonstrated for T+3, T+7, T+30, T+180.

Note honestly: a seeded client-side game can always be computed offline from the public bundle. The
achievable goal is closing the *in-app* rehearsal and widening the window, then documenting the rest as an
accepted gap alongside "codes are client-chosen".

### `noBoardLeft` is broken three ways (`perfect-season.jsx:2702`, `:3032`, `:3117`)

Not in the snapshot, so a reload re-arms the dead board — and a reload is what the note advertises.
`reroll()` never clears it and the re-spin buttons stay enabled, so you can spin to a good board and stay
locked out; take the pick through the ungated tile and the server refuses it anyway. And the note says
"nothing you've drafted here counts against you" while the Reset button five lines up says "counts as a
DNF" — Reset does charge one.

### The mock is a third rulebook

- `tests/mock-supabase.mjs:391` — `replayDraft(seed, history, seq)` with no `{ gm, format }`. Measured
  **6.5–8.9% disagreement** on GM drafts. The headline rule "GM's cap is a reserve" has **zero coverage on
  the submit path**.
- `mock-supabase.mjs:355,360,366,377,384,388,391,404,418` — 400s answered in a *success* envelope, so
  `storage.js:118`'s error-body parse (the only way production learns a `reason`) is executed by no test.
- `mock-supabase.mjs:191,200` — still implements the **pre-fix** `use_account_username`, so the spoofed-name
  fix has no jsdom coverage and the guest chip on Over/Under and builds has none either.
- `mock-profile-data.mjs:195,205` — no guest gates.
- `mock-moderation.mjs:117`, `mock-supabase.mjs:43` — `renameAccount` clears `guest` on `profiles` only.
- `mock-versus.mjs:129-149` — no slot guard, no read error, no deadline error.

### `guest_not_allowed` reaches the player as "check your connection"

`storage-profile.js:82-83` — `SAVE_REASONS` and `AVATAR_REASONS` don't map it, so `rpcReason` falls to
`"network"`. `storage-moderation.js:16` maps it and carries a comment about this exact bug.

### The username tiebreak reached one of five queries

Fixed in `fetchLeaderboardTop` (`storage.js:138`). Missed: `fetchLadderTop:178`, `fetchDailyTop:194`,
`fetchSouTop:201`, `fetchTopBuilds:243`. Worst is Over/Under — small integer scores over one shared round
sequence, so ties at the rank-10 cut are normal and rows genuinely appear and disappear between refreshes.

### `match-pick` — four of five changes need work

- `index.ts:95` — `"slot" in move` is false when the key is **absent**, which is the shape the client
  actually produces (`JSON.stringify` drops `undefined`). Use `move.slot !== undefined && typeof !== "string"`.
- `index.ts:95` — regressed a non-object body from 400 to 500 (`"slot" in move` throws on null/number).
- `index.ts:104` — `"could not read the match"` isn't in `versus.jsx:1105`'s `ERRORS`, so it renders
  "That didn't work." — the generic message the change existed to replace.
- `index.ts:167-168` — the deadline 500 reports a **written** pick as unsaved and doesn't repair the stale
  deadline it warns about. Wants a retry or log-and-continue, not an error.
- `reason: "not_your_turn"` is the wrong word for a bad slot; `bad_slot` exists.
- `submit-run/index.ts:144` never got the same CORS wrapper — the release notes say these move together.

### submit-run hardening

- `history: [null,…]` passes the shape gate then dies on `.key` → CORS-less 500 (`game-logic.mjs:354`).
  Same for a non-string `seq` entry at `:338`.
- `index.ts:91,280` — the profile read's error is discarded, so a dropped read reads as "no profile". Same
  conflation CLAUDE.md has a section about, fixed on the client and left on the server.
- `index.ts:170` — DNF `picks` is unbounded; `picks: 1e12` counts the DNF and overflows the `runs` insert,
  which is swallowed. Clamp to 0..6.

### Data already in production (see §6)

Existing report notes keep their bidi characters; spoofed names written by profile-less accounts survive
the backfill; accounts already holding a guest-shaped name are grandfathered; the runs-log backfill is
**not** idempotent for a stored run with no numeric `date` (measured 1 → 2 → 3 duplicates across passes).

## 6. Pre-flight — run these against production **before** migrating

Read-only. Each was validated against planted bad data. Full text in the sweep transcript; the four that
matter most:

```sql
-- 1. Minigame rows whose account has no profile row: spoofed names the backfill will NOT fix.
--    BAD: any row. Each is a public board entry under a name its account never owned.
select 'sou_runs' as tbl, s.username as shown_as, s.user_id
  from public.sou_runs s left join public.profiles p on p.id = s.user_id where p.id is null
union all
select 'builds', b.username, b.user_id
  from public.builds b left join public.profiles p on p.id = b.user_id where p.id is null;

-- 4. Open reports whose target is a guest. BAD: any row -> dismiss before migrating, or mod_act
--    can still rename the guest into a full account with no way to keep it.
select r.id, r.reason, t.username as target from public.reports r
  join public.profiles t on t.id = r.target_id where r.status = 'open' and t.guest;

-- 5. Stored runs with no numeric date. BAD: any row -> runs-log's backfill inserts a DUPLICATE.
--    Note `is distinct from`: `<> 'number'` is NULL when the key is absent and finds nothing.
select p.id, p.username from public.profiles p
 where (select count(*) from jsonb_array_elements(
          case when jsonb_typeof(p.recent)='array' then p.recent else '[]'::jsonb end) e
         where jsonb_typeof(e->'date') is distinct from 'number') > 0
    or (jsonb_typeof(p.best_run)='object' and jsonb_typeof(p.best_run->'date') is distinct from 'number');

-- 11. Duels in flight. versus-logic's ratingIn changed, so a match drafted before the function
--     deploy is scored by the new rule after it. BAD: any row ->
--     update matches set status='abandoned', ended_at=now() where status='drafting';
select code, status, created_at from public.matches where status = 'drafting';
```

Also worth running: real accounts already holding a `^guest_[a-z0-9]{1,10}$` username; open report notes
containing the stripped character set; and `select user_id, count(*) from runs where backfilled group by 1
having count(*) > 12` to see whether an earlier re-run already duplicated.

## 7. Promotion runbook (corrected)

1. Run the pre-flight queries; resolve anything they find.
2. Abandon duels in flight.
3. Migrations in this order — **runs-log first**, it is not arbitrary (`player_profile` calls
   `player_stats`, which only runs-log defines, and a `language sql` body is validated at creation):
   `migration-runs-log.sql` → `migration-profiles.sql` → `migration-moderation.sql` → `migration-wallet.sql`
4. **Deploy both Edge Functions from `staging`** (`node deploy-function.mjs production`) — *before* the
   merge, not after. See §3.6.
5. Merge `staging` → `master`. The client redeploys itself.
6. Tag `v2.0.0`.
7. Confirm the version in the header, and that the two legacy `*.vercel.app` hosts no longer send
   `X-Robots-Tag: noindex` (they do today; the fixed regex exempts them).

Keep steps 3–5 short: in that window the old client links guest names that `player_profile` now refuses,
and a Championship season with an extreme Flex pick shows one score and stores a lower one.

## 9. Note for whoever picks this up

Three sweeps found ~100 defects. The dominant failure mode, by a wide margin, was **a fix applied to one
call site and not its siblings** — `draft()` has two buttons and one was guarded; `replayDraft` has a
function and a mock and one was updated; `guest_not_allowed` is raised in two functions and mapped in
neither; `capFlex` has two siblings in one file; `fetchProfile` was changed to throw with three of eight
call sites unguarded; a `collate "C"` sweep missed two boards, and the guard written for it missed a whole
file.

**Before fixing anything here, enumerate every call site and every mirror first, fix them as a set, then
verify each one.** The mirrors that matter: `tests/mock-*.mjs` against the SQL and the Edge Functions;
`game-logic.mjs`/`versus-logic.mjs` as used by the browser versus each function; every SQL error code
against the maps in `storage-*.js` and the messages in the components; and the five `.md` files against the
code they describe.

A source-text assertion that matches one spelling is worth very little — two written this way passed
while three real regressions walked by. Prefer driving the real thing, and verify every new test by
reverting its fix and watching it go red.
