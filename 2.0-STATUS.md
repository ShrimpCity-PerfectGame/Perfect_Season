**Written 2026-09-23. Hand this to a new session along with CLAUDE.md.**

2.0.0 is on `staging` at commit `fc6180a`, deployed and verified on the staging site. It is **not
promoted** and should not be until the blockers below are closed. Three adversarial sweeps have been run
(16, ~40 and ~50 findings); sweeps one and two are fixed. **Sweep three is complete — all eight

## 2. What 2.0.0 contains

Bug-fix release, no new modes. The substantial pieces: guests behave like guests everywhere a name is
shown; a patchy connection can't cost you an account; `profiles.rev` stops a finished season being
overwritten by the DNF "Run it back" fires; GM can't deal a board you can't afford anybody on; the bot's
par is measured correctly (seasons had been scoring ~17% low); Championship's Flex is capped so it can't
be drafted into a guaranteed 20–0; accessibility and a 12px floor; security headers and one address per
page; and a service worker that doesn't file OAuth codes.

Two things were **reverted** before release and must not be reintroduced casually:

- **"A re-spin may not repeat a team."** `rerollCandidate` is seeded, so narrowing its pool changes which
  board an existing code deals — 69.7% of team re-spins. Every draft re-spun on the live client and
  finished on the new one would be refused as an illegal roster. Wants server-issued seeds under it, not a
  client-side rule. See CLAUDE.md's note.
- **A `botWalk` reserve based on the real cost of remaining boards.** Measured no benefit; reverted to keep
  the ladder stable.

## 3. Release blockers

Nothing below is speculative — each was demonstrated by a reviewer with a concrete repro.

### 3.1 The roster tile bypasses every draft rule — `perfect-season.jsx:4286` — **FIXED**

`draft()` has **two** call sites. The Lock in button enforces `tooExpensive`, `leavesNothing` and
`noBoardLeft`; the roster-slot tile is `disabled={!target}` and enforces none of them.

```
GM, $19M left, LeSean McCoy $42M on PHI|2
  Lock in:      "🔒 Lock in · Flex - $42M (over cap)"   disabled
  Roster tile:  "Draft LeSean McCoy to Flex"            live
  after tap:    $173M / $150M  →  submit-run: 400 "over the salary cap"
```

**This predates 2.0 and means the GM cap has never been enforced in the UI.** The player is told "it will
be included the next time a save goes through", which is false. Fix both call sites together.

**Fixed.** All three rules moved into one `draftBlock(player)` (`perfect-season.jsx:2244`) that both doors
ask and `draft()` re-checks itself, so a third door inherits them. The tile goes `disabled`, drops its
`target` highlight and says why in its `aria-label`; the admin panel passes `force` and keeps its bypass.
Held by `tests/test-gm-mode.mjs`, which drives a real GM draft from `/c/56RGAK?mode=gm` down to $20M left
and refuses a $38M Ricky Williams at both doors — verified red on reverting the tile's `disabled`, its
`aria-label` and the Lock in button's, each separately.

`draft()`'s own `draftBlock` check is **knowingly unpinned**: React reads `disabled` off the fiber props,
so no click reaches either handler however the DOM node is poked, and nothing in the suite can turn that
line red. It is kept for the third door and both files say so rather than implying coverage.

The assertion that had been standing in for this (`test-economy-security.mjs` 8c) matched
`const tooExpensive = mode.gm && cost > capRemaining;` — one spelling of one line in the door that
worked — and passed for three releases. It now counts the ways into `draft()` (three) and requires the
guard's shape, so a fourth door fails the suite instead of arriving quietly. Both directions verified red.

### 3.2 `botPar`'s rescue can still collapse — `game-logic.mjs:526` — **FIXED**

`if (best == null) return cheap;` returns the spend-least walk with no ceiling applied. `bestPossible`
holds the `MIN_SALARY` reserve and returns null when nothing clears it — i.e. it strands the same way the
greedy bot does, exactly when the rescue is needed.

Demonstrated with code `49BT4M`, GM + Fantasy: a legal $148M roster scoring 94.7 gets par **44.10** instead
of ~93.6 → **649 ladder points instead of ~115**, 64 coins instead of 11, and it clears `SCOUT_MIN_POINTS`
(220) so a below-median season also earns the Scout badge and its 300 coins. One in ~80,000 by accident,
but free-mode codes are the client's own choice, so it is findable offline in seconds.

**Fixed, and the stated mechanism was wrong in a way worth recording.** The reserve is not what strands
`bestPossible`: giving it `botWalk`'s own drop-the-reserve fallback rescued **0 of 99** collapses. A greedy
walk with no handicap spends the most it can on the earliest boards and runs out of the *whole* cap, long
before `MIN_SALARY` matters. So `bestPossible` now searches — one pick per board over (slots filled, cap
spent) — instead of walking. It is null only when the boards cannot field a legal roster at all: 0 of 299
rescues, against 99 for the walk. ~12ms, on the 0.75% of GM drafts that reach it.

`PAR_TYPICAL_SHARE` was re-measured against the new ceiling over 16,000 board sets in both modes and both
formats: median **0.831**, so 0.83 is unchanged — the constant was always describing a real maximum, and
the comment's own quoted band matches the searched ceiling far better than the greedy one it sat next to.

Measured after: rescued par now 85.3–90.2 (was as low as 42.1), and the most a 110-score season can extract
is 220 points, down from 804.

Pinned by two tests in `tests/test-draft-rules.mjs`, both verified red on revert. The first is a reachable
repro found for this — code **`WXEKJ4`**, GM + Fantasy, a roster `replayDraft` accepts at $148M scoring
104.3, which earned **427** points against par 61.2 and now earns 177. (The `49BT4M` board set above could
not be reached by any drafter under the app's own rules, so it would not have made a test.) The second
sweeps 1,500 board sets directly rather than through a probe drafter — which is what hid this: the existing
rescue test's drafter strands on precisely the boards that collapse, so it skipped them. That sweep
independently finds `PARSET976` collapsing to 49.0 on the old code.

**Both Edge Functions must be deployed before the client** (they already must be, §3.7): an old function
and a new client disagree about points on the rescue path, in the old function's favour.

### 3.3 The guest upload gate is cosmetic — `supabase/migration-profiles.sql:650-657` — **FIXED**

`save_profile` and `set_avatar` are gated. The six `avatars` **storage bucket policies are not** — a
reviewer created an anonymous account, watched both functions refuse it, then inserted **10 files**
directly, stopped only by the per-folder cap. Bucket is `public = true`, so each has a working
unauthenticated `gridspin.app` URL, on an account that can be remade indefinitely.

`equip_item` and `set_showcase` (`migration-shop.sql:247,251,255,286`) also write `profile_details` for a
guest, which falsifies `tests/test-profile-data.mjs:147`'s "a refused guest leaves no details row".

**Fixed, as a set.** A new `caller_is_guest()` (security invoker, `profiles` being publicly selectable) is
called by the bucket's **insert and update** policies, beside `uploads_paused` and for the same reason - a
rule on only the insert is sidestepped by overwriting a file already there. Reading and deleting stay open so
anything already in a folder can still be cleared. `shop_buy`, `equip_item` and `set_showcase` raise
`guest_not_allowed`; `shop_state` and `claim_minigame` deliberately do not, because a guest's coins are meant
to wait for them.

The mirrors, all of which were wrong in the same direction: `tests/mock-profile-data.mjs` and
`tests/mock-shop.mjs` (the gates and the mock bucket, plus the `caller_is_guest` RPC);
`storage-profile.js`'s `SAVE_REASONS`/`AVATAR_REASONS` and `storage-shop.js`'s `BUY_REASONS`/`EQUIP_REASONS`/
`SHOWCASE_REASONS`, which is §4's "`guest_not_allowed` reaches the player as check your connection" closed at
the same time; the two screens' message maps; and PROFILES.md, SHOP.md and CLAUDE.md.

The upload has no error code to read - RLS just refuses - so `storage-profile.js` asks `caller_is_guest()`,
the same function the policy calls rather than a second opinion about who is a guest.

Held by: `tests/test-profile-data.mjs` (the real bucket policies in PGlite - add, rename-into-place, and that
read and delete still work, then that it all works once the account keeps its seasons) and
`tests/test-shop-sql.mjs` (the three functions in SQL **and** in the mock, in one test). Verified red on
reverting each of the four SQL gates separately. The client mappings are held by a new pair of tests that read
the raised codes **out of the functions' own source** and require a reason for each - which is the guard that
was missing, since the existing hand-written table is what let `guest_not_allowed` go unmapped for a release.
`tests/test-shop-sql.mjs` already had that guard and it caught the three new codes unprompted.
`tests/test-profile-security.mjs` 6a caught the new function and made it declare itself, which is what it is for.

### 3.4 A failed duel finish bricks Duel permanently — `match-pick/index.ts:159-186` — **FIXED**

The 16th pick inserts, grading fails → 500, `matches.status` stays `drafting`. Both screens sit on
"Working out the result…" and **nothing can post again** (both send paths need `drafting` *and* zero picks
left). Then `create_match` prefers an existing `drafting` match, so tapping Duel returns both players into
the dead match — for every future duel. Recovery is the runbook SQL, by hand.

Second route in: a powerup landing between a concurrent request's match read and its insert silently drops a
pick (`versus-logic.mjs:343-348`'s `take()` returns silently), and grading then returns null.

**Fixed, in three layers, because the brick and its cause are separate problems.**

1. **Finishing is the first thing `match-pick` does**, on any request from either player — it replays the match
   before it looks at what was asked for. Any later request therefore finishes a match stuck that way, and
   `create_match` handing the match back stops being a trap and becomes the repair. `versus.jsx` asks for it
   too: the poll only ever *read*, so nothing had ever poked the server.
2. **`matches.rev`** — the same read-modify-write guard `profiles.rev` is. The three powerup writes are
   conditional `update`s that answer `conflict` when no row comes back; the pick goes through a new
   `record_pick`, which takes the match's own lock, because the decision is made in JavaScript and so cannot be
   inside the transaction that writes it. That closes the race that drops a pick.
3. **`replayMatch` reports what it could not apply** instead of dropping it, and a match with a hole in a roster
   is **abandoned** by the function (`abandon_match`) rather than retried forever — one match instead of the
   feature. The screen for an abandoned match already existed and says the right thing.

Worth knowing: one broken pick is not one hole. What a player takes is gone for both sides and decides which
board comes next, so a dropped pick cascades — three of sixteen, in the test.

**The Edge Function is now executed rather than read as text** (`tests/test-versus-edge.mjs`, through
`tests/edge-match-pick.mjs`, which bundles the real `index.ts`, stubs `Deno` and the handful of query shapes it
uses, and runs it over `tests/mock-versus.mjs`'s own maps). This was worth doing on the first run: it caught a
`ReferenceError` in the fix above — `finish()` is module-level and `json` is a request-scoped closure — which
would have made **every** duel 500 at the sixteenth pick, and which no source-text assertion could have seen.
All four of the function's changes were then verified red on revert, individually. That harness is the answer
to §3.6's "the source-text assertions are the entire guard" for this function; submit-run still has none.

Also fixed on the way: `tests/mock-versus.mjs` mirrors all of it (§4's "no slot guard, no read error, no
deadline error" is narrowed — the read-error and finish paths are now driven against the real function), and a
new match row carries `rev: 0`, because a column with a default is not a field that appears when something
writes it.

**Deploy order:** `migration-versus.sql` must be re-run **before** the functions — the new `match-pick` calls
`record_pick`. The gap the other way is safe: the old function never touches `rev`.

### 3.5 `mod_act` has no guest guard — `supabase/migration-moderation.sql:173` — **FIXED**

`report_player` was gated; the dangerous action wasn't. **Every report already in production against a
guest is a live trap** — `mod_queue` still lists them, Rename still works, and the account ends up
`guest=false` holding a real username on an anonymous session, with `claim_username` answering
`already_named` and `KeepSeasons` gated on `isGuest`. No way to attach an email. See pre-flight query 4.

**Fixed, surgically.** `mod_act` refuses **`rename`** on a guest (`guest_not_allowed`) and nothing else:
`remove_picture`, `clear_bio` and `dismiss` all still work on one, because a bio or picture saved before the
v2.0.0 gate has to be clearable and dismiss is the only way an old report against a guest gets closed at all.
Refusing everything would have left those reports in the queue for good. `mod_queue` carries `guest` on each
entry, `storage-moderation.js` maps it through, and the Reports screen does not offer Rename for one.

**Pre-flight query 4 is now informational rather than required** — an open report against a guest is no longer
a trap, only a thing to dismiss. Running it first is still worth doing to know what is there.

`storage-moderation.js`'s `MOD_REFUSALS` had no entry for `guest_not_allowed` while `REPORT_REFUSALS` next to
it did, so the refusal would have told a moderator their connection had failed. Both tables are now checked
against the functions' own source, as PROFILES.md's and SHOP.md's are.

Found by enumerating rather than by the report: `mod_act`'s rename cleared `guest` on `sou_runs` and not on
`builds`, where `claim_username` clears both — so a renamed account's builds kept the guest chip under its new
name. Unreachable once rename refuses a guest, and made consistent anyway, because the two functions that
rewrite a name snapshot should not differ about what one is. The same bug was in `tests/mock-supabase.mjs`'s
`renameAccount`, where it **is** reachable: it is the trade-up path, so a guest keeping their seasons kept the
chip on two boards in every jsdom test. §4's "`renameAccount` clears `guest` on `profiles` only" is closed.

Held by `tests/test-moderation.mjs` — the SQL, the mock, the queue's flag and the screen's buttons — with each
of the five pieces verified red on revert.

### 3.6 A lost profile update can answer `ok: true` — and its test does not catch it — **FIXED**

`supabase/functions/submit-run/index.ts:101` — `if (written && written.length)` is correct as written, but
the assertion guarding it (`tests/test-economy-security.mjs:1108-1116`) only requires the `ok:true` return
to sit behind an `if` *mentioning* the bound name. Changing it to `if (written)` stays **green**, and
PostgREST returns `data: []` on a zero-row update, which is truthy — so a lost update answers `ok: true`.
That is verbatim the "a personal best could not be recovered" bug `profiles.rev` exists to prevent.

Also green: `if (written.length >= 0)`; `attempt < 5` → `attempt < 1`; the loop falling through to
`return { ok: true }`. Also **red on a harmless rewrite**: `for` → `while`, because the check is
`indexOf("for (")`.

The assertion needs to require a test of *emptiness*, not the mention of a name — or, better, the
behaviour needs a real test. Note `supabase/functions/*/index.ts` is **never executed** by any test; it is
only read as text, and `tests/mock-supabase.mjs` is an independent reimplementation. For both Edge
Functions the source-text assertions are the entire guard.

**Fixed by the better of the two.** `tests/test-submit-run-edge.mjs` runs the real function through
`tests/edge-harness.mjs` (the same harness §3.4 built for `match-pick`, generalised), with another write
landing between `applyToProfile`'s read and its write. Measured against the six edits listed above:

| edit | executed test | the assertion it replaces |
|---|---|---|
| `if (written)` | **fails** | passed |
| `if (written.length >= 0)` | **fails** | passed |
| `attempt < 5` → `attempt < 1` | **fails** | passed |
| no check at all | fails | fails |
| `.eq` moved onto the read | fails | fails |
| `for` → `while` (harmless) | **passes** | failed |

So the source-text half is gone, replaced by a comment recording what it was worth. The test also pins that
the retry re-reads rather than re-sends — the concurrent write's seven wins are still there afterwards — and
that a row that can never be matched is a 500 rather than a cheerful `ok`.

**Both of §5's other assertion holes, closed at the same time** since they sit in the same test:

- The `collate "C"` sweep asked `clauses >= 15` while 22 existed, and only inspected clauses that *remained* —
  so deleting a whole tiebreak lowered the count and passed. It now pins the exact number (23) and says that
  changing it is a decision.
- Its file list never opened `migration-versus.sql`, so **`versus_top` really was ordering by a bare
  `p.username`** — a different order from every other board on production's `en_US.UTF-8`, and from the mock it
  is parity-tested against. Fixed in the SQL, in `tests/mock-versus.mjs` (which sorted with `localeCompare`, a
  third order again), and the sweep now opens all five migrations. Both regressions verified red.

Still open here: the daily-forgery guard's ±2 day window, which the test only forges *today* against.

  green, because the test only forges *today*. `isPlausibleDailyDate` accepts UTC ±1, so tomorrow's and

- That test also hard-codes FNV-1a's constants to build its own collision, so **hardening `hashStr` — the

`test-build-seo.mjs`'s new checks caught 13/13 real reversions (one blind spot: a *second* `/(.*)` header

## 9. Note for whoever picks this up

Three sweeps found ~100 defects. The dominant failure mode, by a wide margin, was **a fix applied to one
call site and not its siblings** — `draft()` has two buttons and one was guarded; `replayDraft` has a
function and a mock and one was updated; `guest_not_allowed` is raised in two functions and mapped in
neither; `capFlex` has two siblings in one file; `fetchProfile` was changed to throw with three of eight
call sites unguarded; a `collate "C"` sweep missed two boards, and the guard written for it missed a whole
file.

**Before fixing anything here, enumerate every call site and every mirror first, fix them as a set, then
verify each one.** The mirrors that matter: `tests/mock-*.mjs` against the SQL and the Edge Functions;
`game-logic.mjs`/`versus-logic.mjs` as used by the browser versus each function; every SQL error code
against the maps in `storage-*.js` and the messages in the components; and the five `.md` files against the
code they describe.

A source-text assertion that matches one spelling is worth very little — two written this way passed
while three real regressions walked by. Prefer driving the real thing, and verify every new test by
reverting its fix and watching it go red.
